# Pre-registration: v18 vs v18 + auditor on the 30 reserved TofuEval upstream-dev documents (written and frozen BEFORE any provider call, 2026-09-30)

Protocol `.local/fresh-eval-v1/protocol.json` (code `fresh_eval.py` sha `e0fe1d1c…`; v18 config `12fc8b550d954359`; auditor prompt sha `f52f7800…`; items digest `c9fe1442…`; labels file sha `fe905c10…`, not read until `report`).
- Population: the 15 + 15 upstream-dev documents the first validation sample did not take; 8 sentences per document (seed 20261101, uses only document ids and row positions; test shows labels do not change the draw) = 240 cases. Inclusion probability π = 8/N_doc (document stage is a census of the reserve), weight 1/π. Bootstrap seed 20261102, 2,000 paired draws, documents resampled within source.
- Pipeline: frozen v18 on all 240; the auditor (unchanged prompt) only on v18 passes; flip iff the auditor's verdict is "unsupported" with a known error type, the disputed assertion is verbatim in the summary, claim/source statements are present and differ, explanation ≥ 8 words. Quote authenticity and overlap are recorded as diagnostics only.
- Spend: ONE journal, hard cap $4.60 across both judges including failed attempts and retries (each HTTP request journaled; bytes-based input bound; invalid/missing usage charged at the reservation; overrun/model mismatch/quota error aborts). Expected ≈ $2.8.
- Kappa: ordinary binary Cohen's κ; "weighted" (primary) = counts summed with w = 1/π, "unweighted" (secondary) = each case once. IMPROVED = corrected > introduced AND lower bound of the 95% paired weighted-κ gain > 0. REACHED_0.74 = pipeline weighted κ ≥ 0.74. Reported separately. Incomplete → comparison withheld. Run once; no rule/threshold/candidate changes afterwards; original held-out untouched.

## Verification that the 30 reserved documents have not informed design (done before freezing)
- No judge call, cache, judgment, exemplar, prompt, rubric, code file or doc references any of the 30 document ids; no 80-character probes from their transcripts occur in any repository, doc or `.local` text file (searched `routebench/`, `docs/`, `.local/`); inventory in `.local/reserve_docs.json`.
- Disclosed exposure (aggregate only): (a) the dev annotation CSVs hold the labels of these documents' sentences; earlier I read aggregate statistics over ALL 35 dev documents per source (sentence counts, ~80% supported, and a count of the published error-type column: Extrinsic Information 141, Nuanced Meaning Shift 69, Reasoning Error 57, Mis-Referencing 35, Tense/Modality 19, Stating Opinion as Fact 15, Contradiction 9 for MediaSum dev) before writing the auditor prompt. The prompt's seven error types are the published TofuEval taxonomy; no per-document or per-sentence content of the reserved documents was used for the prompt, rule, examples or thresholds. (b) The first 40-document sample (not these 30) has v18 results (weighted κ 0.4035) and its false rejections outnumber false passes (40 vs 24), which was known when designing this evaluation.
- Consequence stated in advance: because the auditor can only turn v18 "supported" into "unsupported", it can repair false passes only. On the first sample, fixing every false pass would give κ ≈ 0.68 (< 0.74). 0.74 on this population is therefore unlikely even for a perfect auditor if the same error mix holds; this is descriptive and uses only the first sample, not the reserved documents' labels.
